# 彩票数据实验室（大乐透 · 双色球 · 排列五）

一个开源的彩票历史数据统计与娱乐工具网站：自动同步官方开奖公告，提供走势图、统计分析、历史查询、号码生成器与多方案趣味「预测」。

> ⚠️ 免责声明：彩票开奖为独立随机事件，任何算法与统计方法都无法预测或提高中奖概率。本站所有数据分析与号码推荐仅供娱乐参考，不构成任何投注依据。理性购彩，量力而行；未满 18 周岁禁止购彩。

## 功能

| 模块 | 说明 |
| --- | --- |
| 走势图 | 期号 × 号码网格，遗漏标注、同号轨迹连线，30 / 50 / 100 期切换（排列五为 5 位各自的 0-9 网格） |
| 统计分析 | 号码频率图、冷热榜、当前遗漏排行（红蓝分区）、奇偶比与大小比分布、跨度分布、连号形态、和值走势与分布、号码区间分布（排列五为各位数字频率、当前遗漏、和值/跨度/重复数字分布） |
| 历史查询 | 按期号或日期检索开奖公告，分页浏览 |
| 号码生成器 | 大乐透/双色球：均匀随机机选 + 形态条件过滤（奇偶比 / 大小比 / 和值范围 / 连号限制），自动避开历史重复组合；排列五：5 位数字机选，可均匀或按历史频率加权，多注保证互不重复。进页即出一批，支持整批与单注复制 |
| 号码方案 | 三种方案：**最优**（覆盖优化·最大铺开）/ **次优**（覆盖优化·最小饱和铺开）/ **纯机选**（对照），附全量回测、覆盖率配对检验与置信区间；排列五为去重铺开 / 位置频率偏好 / 纯机选（见下文「排列五」一节） |

数据覆盖：

- **超级大乐透**：自 2007 年首期起（中国体彩网公开接口，gameNo=85）
- **双色球**：自 2013 年起（中国福利彩票官网公开查询接口的数据窗口所限）
- **排列五**：自 2004 年首期起，每日开奖（中国体彩网公开接口，gameNo=350133）

## 本地开发

环境要求：Node.js ≥ 20.9（建议 22+）、npm。

```bash
# 1. 安装依赖
npm install

# 2. 抓取开奖数据（写入 data/dlt.json、data/ssq.json）
npm run fetch

# 3. 本地开发（http://localhost:3000）
npm run dev
```

生产构建与预览：

```bash
npm run build
npm run start        # http://localhost:3000
```

数据抓取脚本其它用法见 `scripts/fetch-data.mjs` 顶部注释：

```bash
npm run fetch              # 增量抓取（默认，与本地数据重叠即停）
npm run fetch -- --full    # 全量重抓
npm run fetch -- --only dlt|ssq|p5   # 只抓指定彩种
```

拟合与验证覆盖优化参数（walk-forward，训练/验证切分，报告写入 `.verify/fit-report.json`）：

```bash
npm run fit                # 大乐透/双色球、默认 5 注（排列五不参与覆盖拟合，见下文说明）
npm run fit -- --tickets 8 # 指定注数
npm run fit -- --game dlt  # 只跑一个彩种
```

## 关于「最优 / 次优」方案（大乐透、双色球）

这两个方案都是**覆盖优化**（唯一对机选有真实、可复现优势的做法），差别只在铺开强度：

| 方案 | 铺开强度 | 含义 |
| --- | --- | --- |
| 最优方案 | 最大 | 红区、蓝区都尽量不重号，同价位覆盖最多不同号码 |
| 次优方案 | 最小饱和 | 在「覆盖率不显著下降」的前提（与最优差距 ≤1 个标准误）下取最小铺开，号码更集中 |
| 纯机选 | 无 | 均匀随机，对照组 |

- **它们都不预测号码。** 开奖是均匀随机事件，单注命中期望 `(每注号码数/号码池) × 每注号码数`
  对任何选号方式都相同——页面上三个方案的「平均每期命中」都在随机期望的噪声带内。
- **优化的是同价位多注之间的号码分配**：依据 `P(∪Aᵢ) = ΣP(Aᵢ) − ΣP(Aᵢ∩Aⱼ) + …`——每注自身的
  中奖概率固定，减少各注之间的重叠就能提高「至少中得某奖级」的概率，而不是提高任何一注的概率。
- **实测**（全量 walk-forward，与同注数机选逐期配对比较，5 注）：

  | 指标 | 大乐透·最优 | 大乐透·次优 | 双色球·最优 | 双色球·次优 |
  | --- | --- | --- | --- | --- |
  | 至少中得某奖级 | 33.7% vs 机选 29.5% | 33.8% | 30.9% vs 27.1% | 30.0% |
  | 蓝区至少命中 1 个 | 98.5% vs 85.7% | 98.5% | 29.8% vs 25.5% | 28.8% |
  | 红区至少命中 2 个 | 62.1% vs 52.4% | 61.2% | 95.2% vs 85.0% | 94.5% |
  | 红区至少命中 3 个 | 无显著差异 | 无显著差异 | 无显著差异（验证段） | — |
  | 单注平均命中 | 无显著差异 | 无显著差异 | 无显著差异 | 无显著差异 |

  注数为 1 时没有可铺开的空间，与机选逐期完全相同；它**不会**让你中得更大的奖。
  页面内会实时重算一遍并给出配对 95% 置信区间与 p 值，同时把「单注平均命中与机选无差异」
  一并列出——两件事必须成对呈现，否则容易被误读成「能预测号码」。

## 关于「排列五」方案

排列五是数字型玩法（5 位有序数字、每位 0-9、可重复、可有前导 0），**只有一个奖级**（5 位全中，
概率 1/100000）。因此这里没有「更准」的方案可言：

- 任意一注的中奖概率都是 1/100000，与怎么选号无关；买 N 注时只要**互不重复**，概率就是 N/100000。
- 唯一真实的优化只是**别买重复注**：机选 5 注约有 0.01% 的概率出现重复注（撞掉的那注等于白花钱），
  折算到「每 10 万注期望中奖注数」是 5.000000（去重）vs 4.999900（机选）——真实但极小，
  实测 7723 期中机选只有约 0.75 期会出现重复注，所以页面以**解析概率**为准。
- 因此三个方案如实分为：**最优**＝均匀随机＋强制去重（唯一真实优化）、
  **次优**＝按各位历史频率加权＋去重（**不改变中奖概率**，只是选号口味）、**纯机选**＝允许重复的对照组。
- 页面上直接写出「单注 1/100000」「三档中奖概率相同」，并给出每注平均命中位数（理论恒为 0.500 = 5×1/10）
  作为「选号方式不影响命中」的证据。

## 数据来源

- **大乐透**：中国体彩网 webapi.sporttery.cn（官方公开接口，需带浏览器 UA 与 Referer）
- **双色球**：中国福利彩票官网 www.cwl.gov.cn（官方公开接口，需带浏览器 UA + Referer）
- 抓取脚本对每条记录做号码数量、范围与重复校验，保证入库数据可用

**更新链路**（线上实际机制，与直觉不同）：

- 官方接口屏蔽海外机房 IP（体彩 HTTP 567 / 福彩 403），所以 **GitHub Actions 里抓不到数据**。
  `update-data.yml` 每天按北京时间 22:05 / 23:35 / 次日 01:35 / 09:35 / 12:35 / 15:35 / 18:35
  多次运行，抓取失败不阻断，最后用 `scripts/check-freshness.mjs` 校验数据新鲜度——漏抓就让
  Actions 变红，起「看门狗」作用。
- **数据实际由本地 Windows 计划任务 `LotteryDataSync` 抓取**（用 `scripts/setup-sync-task.ps1`
  注册：每日 09:40 / 12:40 / 15:40 / 18:40 / 22:10 / 23:10 + 登录时触发；先抓取并本地提交，
  再 pull --rebase + push，直连失败自动改走本机 7890 代理），推送后 Vercel 自动重新部署。
- 因此数据能否更新取决于这台 Windows 机器是否在线；CI 只能发现漏抓，不能替代它。
  数据体检可运行 `npm run audit`（格式/范围/去重/日期星期/号码频率卡方）。

## 部署

站点为纯静态输出，可在任意托管平台部署；以 Vercel 为例：

1. 将本仓库推送到 GitHub（建议先设为私有仓库）
2. 在 [Vercel](https://vercel.com) 中 **Add New → Project** 导入该仓库，框架选择 Next.js，其余保持默认，点击 Deploy（零配置）
3. 部署完成后在 Vercel 项目 Settings 中：
   - 绑定自定义域名（站点默认域名已内置为 `https://lottery-predict.com`，可在 DNS 面板将域名指向 Vercel）
   - 添加环境变量 `SITE_URL=https://你的域名` 覆盖默认域名（影响 `/sitemap.xml` 与 `/robots.txt`）
4. GitHub Actions 每日自动同步数据；也可在仓库 **Actions → 每日开奖数据更新 → Run workflow** 手动触发一次验证

## 性能约定

页面（服务端组件）通过 `src/lib/compact.ts` 把开奖数据编码成定宽字符串再传给客户端组件——
直接传 `Draw[]` 会让 RSC payload 带上每期的键名与括号（排列五页面因此到过 450KB）。
客户端组件在 `useMemo` 里解码一次，子组件接口保持不变。

echarts 由 `EChart.tsx` 在挂载后动态加载（`import("echarts/lib/chart/bar")` 这类深层路径，
导入即自注册），因此走势表页面的首屏不下载图表脚本；新增图表类型时要在 `loadEcharts()`
的 import 列表里加对应深层模块（渲染器不自注册，需显式 `use(install)`）。

预测页的初始参数（大乐透 / best / 5 注 / seed 1）在构建期预计算并作为 props 传入，
水合时不再全量回测——改这两页的初始参数时，`page.tsx` 里的预计算要与组件里的判据保持一致。
