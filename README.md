# 号码手记

面向超级大乐透、双色球、排列五的免费历史数据与选号娱乐工具。首页直接展示当期号码搭配，也可以记录自己的号码、核对已公布的开奖结果。走势图、统计分析和方法回测保留在详情页，供想研究历史数据的用户查看。

> ⚠️ **免责声明**：彩票开奖为独立随机事件，任何算法与统计方法都无法预测开奖结果或提高单注中奖概率。本站的统计、号码推荐与动画仅供娱乐参考，不构成投注依据。请理性购彩、量力而行；未满 18 周岁禁止购彩。

## 从首页开始

| 功能 | 用法与边界 |
| --- | --- |
| 当期主推荐 | 打开首页即可查看所选彩种的固定 5 注；同一开奖周期内自动保存，不因刷新或换备选而改变。大乐透与双色球优先减少同批号码重叠，排列五提供互不重复的号码。支持整组复制。 |
| 其他备选 | 点击「看看其他备选」生成新的一组，可对单注点「喜欢」或「收藏」。喜欢会成为个性化偏好；收藏只保存号码。 |
| 猜您喜欢 | 根据用户明确喜欢或录入的已购号码，在同一彩种内生成另一组 5 注。参考常选号码、奇偶、连号和和值，并保留不同选择；它表达选号口味，不代表更容易中奖。没有偏好记录时会提示从一注开始。 |
| 我的号码 | 按每行一注录入普通单式购买号码，或查看自动保存的推荐、个人推荐和手动收藏。可修改、删除已购记录，撤销喜欢或清空偏好学习。系统推荐、自动保存和收藏本身不参与学习。 |
| 开奖核对 | 记录绑定选定的历史期号，或接续最新一期等待下期开奖。官方结果进入数据文件后，按号码显示命中情况与奖级；数据未更新时显示等待，不提前判为未中奖。 |
| 开奖动画回放 | 首页「最近一次开奖」下方点击「开奖动画回放」，可切换三个彩种、输入已收录的历史期号，支持暂停、继续、倍速、跳过和重播。大乐透、双色球使用独立红蓝球池，区内随机模拟出球顺序；排列五按五个位置分别模拟 0–9 号球，保留重复数字和前导 0。最终号码来自真实公告，动画不代表现场出球顺序或录像。 |
| 每次刷新换句名言 | 推荐页顶部轮换数学、概率与哲学短句，显示作者和可点击的出处；连续刷新会避开上一句。 |

所有个人号码与偏好仅保存在当前浏览器的 `localStorage`，无需账号，也不会跨设备同步。清除浏览器站点数据会丢失本地记录。开奖结果来自构建时打包的历史数据；只有数据文件更新并重新部署后，网站才会显示新一期。

三个彩种的历史页面分别为 `/dlt`、`/ssq`、`/p5`，提供统计分析、走势图和按期号或日期查询。高级条件选号在 `/generator` 与 `/p5/generator`；方法说明和回测在 `/predict` 与 `/p5/predict`。这些研究功能不会改变首页已保存的主推荐。

大乐透历史数据自 2007 年首期起，双色球自 2013 年起（受福彩公开查询窗口限制），排列五自 2004 年首期起。大乐透、排列五取自中国体彩网公开接口，双色球取自中国福利彩票官网公开接口。发现与官方公告不一致时，以官方公告为准。

## 推荐方法的边界

大乐透和双色球的「充分铺开」「适度铺开」「纯机选」是三种**同价位多注之间的号码分配方式**。前两种尽量减少同批号码重叠，差别在铺开程度；第三种是均匀随机对照。铺开影响的是一批号码覆盖多少不同号码，以及历史回测中「至少中得基本奖级」的比例，**不会提高任一单注的中奖概率**。只有 1 注时没有铺开空间，和机选相同。

首页主推荐使用充分铺开的搭配。奇偶、连续号和和值会用于说明号码形态，也会温和地参与「猜您喜欢」的偏好搭配；它们不会被解释为下期信号。历史频率与形态权重候选经过训练段、验证段的检验，未得到稳定增益，因此系统默认推荐不启用这些权重。完整回测以 `npm run fit` 当前生成的报告为准，不把某次历史表现当作未来承诺。

排列五是五位**有序**数字，每位可以是 0–9，允许重复和前导 0，例如 `06940`。任意一注的中奖概率都是 `1/100000`；不同选号方式的单注概率相同。多注之间去重可以避免买到完全重复的一注，收益极小；位置频率方案只改变选号风格。

双色球部分期次可能涉及特别奖级。本站历史数据不包含特别奖的启停状态，相关匹配会标记为「待核实」，请以官方当期公告为准。

## 本地运行与验证

建议使用 Node.js 24 和 npm。仓库已包含 `data/*.json`，只想运行网站时无需先抓取数据。

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # 生产构建与 TypeScript 检查
npm run start        # 预览生产构建
```

数据与算法维护命令：

```bash
npm run fetch                     # 增量抓取三个彩种的官方数据
npm run fetch -- --full           # 全量重抓
npm run fetch -- --only dlt       # 也可指定 ssq 或 p5
npm run audit                     # 只读数据体检
npm run fit                       # 大乐透/双色球覆盖参数拟合与验证
npm run fit -- --tickets 8        # 指定注数
npm run fit -- --game ssq         # 指定彩种
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/verify-workspace.mjs
npx tsc --noEmit
```

`npm run fit` 只读 `data/*.json`，报告写入本地忽略目录 `.verify/fit-report.json`。验证按开奖先后逐期使用此前可见的数据选号，参数在前 70% 历史中拟合，后 30% 用于检验；与机选做同期配对比较，并报告单注平均命中，避免把抽样波动解释成预测能力。

## 数据更新与部署

网站是 Next.js App Router 的预渲染站点。页面在**构建时**读取 `data/dlt.json`、`data/ssq.json`、`data/p5.json`，没有在线开奖接口、账号系统或数据库。新的开奖数据必须提交并推送这些 JSON 文件，触发 Vercel 重新构建；只更新本地文件不会改变线上页面。

官方接口会屏蔽机房 IP，GitHub Actions 中的抓取失败因此被保留为非阻断警告。实际更新由本地 Windows 计划任务 `LotteryDataSync` 执行抓取、提交和推送；Actions 最后运行 `scripts/check-freshness.mjs` 监测是否漏抓。新增彩种时还需同步 `scripts/sync-data.cmd` 的 `git add` 列表。

部署到 Vercel 时导入本仓库，按 Next.js 项目构建即可。站点域名可通过环境变量 `SITE_URL` 设置；未设置时使用 `https://lottery-predict.com` 生成站点地图和爬虫配置。开奖时间、期号格式及数据来源由各彩种配置维护，时间按北京时间解释。

## 项目结构

```text
data/                         三个彩种的历史开奖 JSON
scripts/fetch-data.mjs         官方数据抓取
scripts/audit-data.mjs         数据体检
scripts/fit-coverage.mjs       覆盖参数拟合与验证
scripts/verify-workspace.mjs   选号、期号与记录逻辑验证
src/app/                       首页、历史、生成器、方法与关于页面
src/components/LotteryWorkspace.tsx  首页推荐与号码簿入口
src/components/DrawReplay.tsx        三彩种历史开奖动画
src/components/RefreshQuote.tsx      首页名言轮换
src/lib/notebook.ts            本地记录、偏好与开奖核对
src/lib/recommendation.ts      首页系统号码与推荐说明
src/lib/predict.ts             组合型方案与回测
src/lib/digit-predict.ts       排列五方案与回测
src/lib/compact.ts             历史数据紧凑传输编码
```

服务端页面将历史开奖压缩后传给客户端，避免重复传输每期的字段名。ECharts 在打开图表时按需加载；开奖回放组件在用户打开时加载。项目使用 React、TypeScript、Tailwind CSS 4 与 ECharts 6。
